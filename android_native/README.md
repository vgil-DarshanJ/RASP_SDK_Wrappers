# RASP Shield Native — Kotlin/Java Android SDK (no Flutter)

Full detector-catalog parity with the Flutter plugin — 42 on-device detectors
across device integrity, runtime protection, app integrity, network security,
privacy/screen, fraud signals and risky-app intelligence (the list:
`docs/PRODUCT_FACTS.md` in the engine repository) — plus Play Integrity
attestation. Zero license, zero activation, zero Flutter dependency.

This guide shows the recommended path: `RaspLeanSession`, the same
config-driven orchestration layer the Flutter plugin uses, which owns
polling and automatically ships events to your RASP Shield dashboard. (If
you need to call individual detectors yourself with no polling loop at
all, `RaspShieldCore` — the lower-level API this session is built on — is
documented in `../flutter/rasp_shield_sdk/docs/ANDROID_NATIVE_SDK_REFERENCE.md`.)

---

## Before you start: two things you need from the dashboard

1. **Register your app.** RASP Shield dashboard → **Applications** →
   **Register application** → pick **Android Native**. Download the
   issued `credential.json` — shown once, keep it safe.
2. **Download the SDK.** Same card → **Download SDK**. It contains one
   folder: `android_native/`. (The detection engine itself,
   `android_core`, is **not** in this zip — see Step 1, it's resolved by
   Gradle automatically instead.)

---

## Step 1 — Add the JitPack repository

`android_core` (the actual detector implementations) is published via
[JitPack](https://jitpack.io) rather than bundled as source you copy in.
Open your app's **root `build.gradle.kts`** (or wherever your project
centralizes repositories — see the note below) and add one line to the
existing repositories block:

```kotlin
// build.gradle.kts — your app, BEFORE
allprojects {
    repositories {
        google()
        mavenCentral()
    }
}
```

```kotlin
// build.gradle.kts — your app, AFTER
allprojects {
    repositories {
        google()
        mavenCentral()
        maven { url = uri("https://jitpack.io") }   // ← add this line
    }
}
```

**If your project instead centralizes repositories in
`settings.gradle.kts`** (common in projects generated by recent Android
Studio versions), it looks like this instead — same one line, different
file:

```kotlin
// settings.gradle.kts — if your project has this block instead
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        google()
        mavenCentral()
        maven { url = uri("https://jitpack.io") }   // ← add this line
    }
}
```

Skipping this step produces a clear, specific Gradle error naming
`com.github.Vedant0Nisar:RaShield-SDK` as unresolvable — not a silent
failure, and not something a rebuild without this line will fix.

## Step 2 — Add the module to your project

Unzip the downloaded SDK so `android_native/rasp_shield_native/` sits
somewhere your project can reference — e.g. alongside your app:

```
YourApp/
  app/
  rasp_shield/
    rasp_shield_native/     ← the unzipped folder
```

Then, in your app's `settings.gradle.kts`, add the include (this is the
**only** module you need to include now — `android_core` is resolved
automatically via the repository you just added, not as a local module):

```kotlin
// settings.gradle.kts
include(":rasp_shield_native")
project(":rasp_shield_native").projectDir =
    File(rootDir, "rasp_shield/rasp_shield_native")
```

And depend on it from your app module:

```kotlin
// app/build.gradle.kts
dependencies {
    implementation(project(":rasp_shield_native"))
}
```

## Step 3 — Wire it into your app's startup

Pick your `Application` subclass or your main `Activity`'s `onCreate` —
wherever your app already does startup work. Here's a full before/after
against a bare-bones `Application` class:

```kotlin
// YourApplication.kt — BEFORE
package com.yourbank.app

import android.app.Application

class YourApplication : Application() {
    override fun onCreate() {
        super.onCreate()
    }
}
```

```kotlin
// YourApplication.kt — AFTER (added lines marked)
package com.yourbank.app

import android.app.Application
import com.shieldsdk.rasp.RaspEventShipper                              // ← add
import com.shieldsdk.rasp.nativeshield.RaspLeanSession                  // ← add
import com.shieldsdk.rasp.nativeshield.RaspLeanConfig                   // ← add

class YourApplication : Application() {
    override fun onCreate() {
        super.onCreate()

        // First launch ever: load the credential.json you downloaded and
        // paste its contents below (or read it from your own secure
        // config at release time — don't hardcode it long-term). Every
        // launch after that, restore() reads it back from encrypted
        // storage automatically.
        if (!RaspEventShipper.restore(applicationContext)) {
            val credentialJson = """<paste your downloaded credential.json contents here>"""
            RaspEventShipper.configureAndPersist(applicationContext, credentialJson)
        }

        // Starts the background poll/ship loop — the only place you
        // choose which of the 42 detectors are active. See your
        // dashboard's /guide page for the full detector table and what
        // you're exposed to if you leave one off.
        RaspLeanSession.start(
            context = applicationContext,
            config = RaspLeanConfig(
                screenshotProtection = true,
                usbDetection = true,
                adbDetection = true,
                rootDetection = true,
                fridaDetection = true,
                hookDetection = true,
                tamperDetection = true,
                untrustedInstallSourceDetection = true,
                mitmDetection = true,
                overlayDetection = true,
                accessibilityDetection = true,
            ),
        )
    }
}
```

If you want screenshot protection to actually apply (it needs a live
`Activity`, not just a `Context`), pass `activityProvider` too, from
whichever Activity is currently in the foreground:

```kotlin
// TransferActivity.kt — a screen showing sensitive data
class TransferActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        val session = RaspLeanSession.start(
            context = applicationContext,
            config = RaspLeanConfig(screenshotProtection = true /* ...plus whatever else */),
            activityProvider = { this },   // ← lets FLAG_SECURE actually apply here
        )

        session.setListener { state ->
            val root = state.extendedDetectors["root_jailbreak"]
            if (root?.status?.isThreat == true) {
                // your policy: finish() this Activity, force logout, etc.
            }
        }
    }
}
```

Register your `Application` subclass in `AndroidManifest.xml` if you
haven't already (`android:name=".YourApplication"` on the `<application>`
tag) — a fresh Android Studio project doesn't have one by default, so
this is the one manifest edit this integration needs.

That's the whole integration. Build and run, then check your dashboard's
**Live Threats**/**Devices** page — events should appear within seconds.

## Exception-handling contract

Identical to the Flutter path — see
[the Flutter integration guide's own section on this](../flutter/rasp_shield_sdk/docs/LEAN_SECURITY_INTEGRATION_GUIDE.md#exception-handling-contract-read-this-once-it-explains-will-it-crash)
for the full explanation (5-state contract, crash isolation via
`runGuarded`, the one network-calling detector's timeout behavior, and the
two flags — `clipboardProtection` auto-clear and `screenshotProtection` —
that change real app behavior, not just detection).

## Full method reference

See `../flutter/rasp_shield_sdk/docs/ANDROID_NATIVE_SDK_REFERENCE.md` for
the lower-level `RaspShieldCore` API (every detector as a direct
`checkXBlocking`/`checkXAsync` call, for cases where you need one-shot
checks with no polling loop), the complete 5-state contract, required
manifest permissions, R8/ProGuard keep-rule requirements, and
platform-version gates.

## Requirements

- `minSdk 23+`, Kotlin Android Gradle plugin applied (standard in any
  modern Android Studio project; required even if the rest of your app is
  Java, purely to compile the `.kt` sources this SDK pulls in)
- `INTERNET` permission (for the network-based detectors — high-risk-IP
  lookup, MITM/proxy check, and Play Integrity's own client library;
  merges automatically from `android_core`'s manifest)
- No other permissions; the curated `<queries>` package-visibility
  declarations `android_core` needs also merge automatically
